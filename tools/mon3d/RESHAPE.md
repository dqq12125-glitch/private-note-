# 把「纸片一样扁」的怪兽重新做成立体的（2026-11-24）

老板 2026-11-24：「现在开始来完善这些怪物的那些模型，因为现在还是像纸片人一样。」

## 查出来的情况

- 全部怪兽里 18 只没有模型（`hold.txt`，对战里是一张朝着镜头的原画），约 50 只的模型是一张薄片：从背后看还是一张脸、侧过来只有一条线。
- 一上来就会遇到的几只正好都在里面（雨滴滴 #4、小熔岩 #14、雾团 #17、小贝壳 #26、水花花 #31）。
- **原因**：原画是正面、平涂、没有明暗的卡通画，Hunyuan3D 的「形状」那一步看不出厚度。换种子没用——雨滴滴试了 6 个种子，厚度比最好 0.23；水花花 6 个里 5 个是 0.01（真的一张纸）。
- 以前的补救是绑骨骼时写 `thick`（沿左右方向硬拉厚）。试过把现成的薄片沿前后拉厚 3 倍：变成一本带脸的厚书，不能用。
- iPhone 的内核（WebKit）读得出发布的模型（带骨骼的那种），不是「没加载出来」。

## 做法：先给原画补出立体的明暗，再生成形状

`tools/mon3d/puff.py`：按轮廓把原画「吹鼓」——在轮廓里解一遍「吹气球」（泊松方程，边上是 0、里面往上鼓，出来是光滑的鼓包），算出法线，打一盏左上方的灯，边上压暗、鼓的地方提亮。颜色还是原画的颜色，看着像一个鼓鼓的玩具。

- **形状**用补了明暗的图生成（`gen.py --src=puff --notex --pca`）；
- **贴图**还是用原画（`gen.py --noshape --src=src1`），所以颜色、花纹和原来一样。

效果（厚度比 = 顶点主成分最薄 / 最长）：雨滴滴 0.23 → 0.55，小熔岩 0.18 → 0.59，都是第一个种子就成。带大鱼鳍的水花花不行（0.01 / 0.02 / 0.14），要另想办法（见下面「没做的」）。

## 第二个办法：不用生成模型，自己从原画的轮廓吹出一个壳

老板 2026-11-24：「你不能用 Blender 自己做吗？为什么一定要那个模型呢？」——能，给补了明暗也还是薄片的那几只用（带大鳍、大翅膀的）。

`tools/mon3d/inflate.py <id> --tag=i1`（不用显卡，十几秒一只）→ `art/hy3d/<id>_raw_i1.glb`：

- 形状：在轮廓里解「吹气球」（和 puff.py 同一个办法），身体宽的地方厚、鳍和尾巴这种窄的地方薄（`--pow`，默认 0.62）；最厚处是最宽处一半的 0.62 倍（`--depth`），像一个鼓鼓的靠垫。前后各一面，轮廓边上留半格厚、用一圈侧壁接起来——是一个真正封闭的壳。
- 贴图：正面就是原画；背面把轮廓里面靠外一圈的颜色往里抹开，脸和肚皮就没了；陡的地方（靠近轮廓边）两面都换成抹开的身体颜色，不然原画的黑边在侧面会被拉成黑条。
- 骨骼：原来的骨骼文件是照原画的画面量的，直接能用（水花花：`RIG … unweighted verts 0`）。

和生成的比：正面和原画一模一样，侧面、背面有厚度；但它是「印着图案的布偶」——手脚、鳍不单独鼓出来，鳍偏厚，侧面还有一点拉花。**能生成成功的还是用生成的**（雨滴滴那种明显更好），这个只当退路。

踩过的坑：第一版让轮廓边上的厚度是 0、靠合并顶点把前后两面合拢——细的地方（一两格宽）前后两面叠成没有厚度的重叠面，Blender 的自动权重（热扩散）整只都算不出来（`Bone Heat Weighting: failed`，导出来没有骨骼）。现在边上留半格厚 + 侧壁，合并顶点以后没有开口、没有非流形的边。

## 第一批 51 只的结果（2026-11-24 晚）

`hold.txt` 的 18 只 + 最扁的 33 只，全部重做、绑好骨骼、发布了：**现在每一只怪兽都有会动的 3D 模型，`hold.txt` 空了**（对战里不再有原画纸片）。

- 形状：一只 1.5–4 分钟（第一个种子够厚 95 秒，三个都试完 255 秒），贴图一只约 1 分钟，51 只前后 3 小时多（RTX 5060 Ti）。
- `reshape.sh` 按 gen.py 的数（最薄 / 最长）0.40 划线，36 只过线、15 只「偏薄」。把这 15 只的正面 + 侧面渲出来看（`tools/blender/gridview.py`），**都有真的厚度**——蛇、长尾巴的、举着大尾巴的，「最长」那个方向本来就长，这个数冤枉它们。照样贴了图用。以后别只看这个数：看 `flatscan.py` 的 `paper`（最薄 / 中间），再看一眼侧面。
- 真的还扁的只有侧着画的鱼（小池鱼 `pondlet`）和鳐鱼（`tidewing`）：它们本来就是扁的东西，新模型和旧的差不多。明暗加重（`K=1.6`）再试没有用（0.02–0.26、0.16–0.18），就用第一遍的。
- 骨骼：36 只原来有骨骼文件的，**一只都不用改**（形状是照同一张原画生成的，朝向、比例都对得上）。15 只以前没有 3D 模型的新写（分给三个便宜模型的助手，每人 5 只，两分多钟）；它们写的时候模型还没贴图、是灰的，**15 只里 3 只朝向定错了**（花粉团、丝球、幽帆：把正面的当成侧面，写了 `yaw: ±90`）——贴好图以后在对比图里一眼看得出来（正面那一格看到的是侧脸 / 后背），改了。以后写骨骼等贴好图再写，或者写完一定在贴了图的对比图里看一遍朝向。
- `monrig.py` 顺手修了一处：和身体不连着、里面也没有骨头的小零件（`joyburst` 头顶迸出来的小星星）自动权重算不出来，以前就停在原地、身体倒下了还悬在半空；现在整个挂到最近的那根骨头上（输出里多一行 `LOOSE <id> n verts`）。
- 验收：三批对比图（`vdiff.js`，每只：旧的 | 新的我方 / 正面 / 对手出招）一只只看过；`fxcheck.js` 51 只在真的对战里都没有报错。

## 怎么量扁不扁

`D:/Claude/tools/hy3d/Scripts/python tools/mon3d/flatscan.py --dir=art/mon3d --suffix=.glb`：顶点主成分三个方向 a ≥ b ≥ c，
`paper = c / b`（最薄比中间）——纸片这个数很小，蛇、龙这种细长的不会被冤枉。2026-11-24 量绑好骨骼的母版：< 0.2 有 8 只、0.2–0.3 有 17 只、0.3–0.4 有 26 只、≥ 0.5 有 262 只。
这一轮重做的是 `hold.txt` 的 18 只 + `paper < 0.35` 的 33 只（一共 51 只，按手册编号排，越早遇到越先做）。`paper` 在 0.35–0.4 的 13 只、0.4–0.5 的 62 只没动（偏薄，但不算纸片；要做就照下面再跑一批，一只约 4 分钟）。

## 一步步

```bash
# ① 形状 + 贴图（显卡，一只 3–6 分钟；不动现成的 _raw.glb，不绑骨骼，不发布）
bash tools/mon3d/reshape.sh p1 <id> [id ...]
#   结果 art/hy3d/reshape-p1.txt：每只一行「id 厚度 种子 ok / thin / flat」；ok 和 thin 的有 art/hy3d/<id>_raw_p1.glb
#   换种子 / 明暗重一点：SEEDS=7,1,3 K=1.6 bash tools/mon3d/reshape.sh p2 <id> ...

# ② 换上去（旧的留一份）、绑骨骼、看检查图
cp art/hy3d/<id>_raw.glb art/hy3d/<id>_raw_flat.glb      # 第一次才留
cp art/hy3d/<id>_raw_p1.glb art/hy3d/<id>_raw.glb
bash tools/mon3d/rigtool.sh rig <id>                     # 读 tools/mon3d/rigs/<id>.json → art/mon3d/<id>.glb + art/mon3d/check/<id>.png
#   形状是照同一张原画生成的，正面的轮廓差不多，原来的骨骼多半还能用；检查图里手脚被拉长、身体撕开的，照 RIGGING.md 改关节。
#   原来靠 "thick" 硬拉厚的，新模型已经够厚了：把 "thick" 删掉。没有骨骼文件的（原来没绑过）照 RIGGING.md 新写。

# ③ 发布、对比、放进真的对战里看
node tools/mon3d/publish.js <id> [id ...]
node tools/mon3d/vdiff.js --a <旧的发布版目录> --b assets/mon3d --ids <id,…> --sheet-ids <id,…> --views me:idle,foe:idle,front:idle --label reshape
node tools/mon3d/fxcheck.js --pairs <id>:<id>
#   原来在 hold.txt 里的：发布以后从 hold.txt 删掉（游戏就不再用纸片）；regen.txt 里的也删掉
```

旧的发布版从 git 里取：`git show HEAD:assets/mon3d/<id>.glb > <目录>/<id>.glb`。

## 验收（每只都要看图，不能只看数）

- 厚度：`reshape.sh` 标 `ok` 的直接过；标 `thin` 的（0.25–0.40）渲侧面看一眼，细长的东西这个数偏低不要紧；`flat` 的（< 0.25）没贴图，要么本来就是扁的东西（鱼、鳐鱼：`PAINT=0.15` 再跑一遍给它贴上），要么换办法；
- 对比图里从背后看（`me:idle`）不再是一张脸；
- 检查图四个动作（待机、走路、攻击、倒下）手脚不拉长、不撕裂；
- `fxcheck.js` 没有报错。

## 没做的、要知道的

- **带大鳍、大翅膀的（水花花这种）补了明暗还是薄**：用上面「自己吹壳」的办法（水花花已经这样做了）。明暗重一点（`K=1.6`）试过没有用。不用再下载别的模型。
- 自己吹的壳还能再好：鳍偏厚（没有分出哪块是身体、哪块是鳍）、侧面有一点拉花。
- 贴图那一步有时在肚子、背上留一道接缝（雨滴滴正面有一小块），没处理。
- 改动只在对战和新画风的大地图里看得到；手册、队伍里一直是 2D 图标。
- 这是「形状」的事。所有怪兽的贴图都带着原画的黑边和平涂，打光也偏平，看着像贴纸——这一条还没动（另一件事：改材质，让明暗分得更开、加一圈边缘光）。

## 背后又画了一张脸的（2026-11-24 晚）

形状立体了以后，从正背后把 51 只都渲了一遍（`gridview.py` 转 180°）：大多数背后是正常的后背，**7 只背后又是一张脸**
（雾灵灵 `mistlet`、雾团团 `foglet`、纸鸢灵 `paperkite`、潮翼 `tidewing`、符文石 `runelet`、幽灵帆 `ghostsail`、电风筝 `boltkite`）。
原画是正面朝着看的人画的，贴图那一步看不到背后，就把正面照搬过去了。对战里镜头不到背后、看不出来；新画风的大地图里跟着走的怪兽正是从背后看的。

`tools/mon3d/backfix.py <id> …`：形状不动，只改贴图——从正背后把模型「拍」成一张图，离轮廓近的一圈照旧，里面的（脸、肚皮、花纹）
用这一圈靠里那一半的颜色按远近平均着抹开，再写回贴图（只写朝后的、从背后看最外面的那层；侧面和正面不动）。两秒多一只。
出来是 `art/hy3d/<id>_raw_bf.glb`，换成 `_raw.glb` 再 `rigtool.sh rig`、`publish.js`。`--debug` 存一张「改之前 | 抹的颜色 | 改之后」。

- 7 只都这样改了：背后是一个光光的后背，正面看不出差别（对比图里我方、正面、对手三个角度都核对过，轮廓重合 99.9%）。
- 试过 `cv2.inpaint`：抹出一道道扇形的印子；颜色要是连最外面的黑边一起取，背后会发黑。
- 只适合正面朝着看的人画的那种。侧着画的（骨骼文件里 `yaw` 是 ±90 的）别用：它们模型的「背面」是身子的另一侧，花纹该留着。
- 抹掉的只是画上去的脸；脸的鼓包（鼻子、嘴的起伏）还在形状里，凑近看得出一点。
- **别的怪兽没查**：这一批以外的三百多只里，正面画的应该还有不少背后带脸的。要查：每只从背后渲一张、挑出带脸的、跑 `backfix.py`、重新绑骨骼发布。
