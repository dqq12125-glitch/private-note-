# 🎓 学生跟进 · 留学 / 签证客户管理

替代 Excel 的学生客户跟进网站：写记录不用手打日期、自动提醒下一步和 offer DDL、每个学生有完整时间线，重要的排前面，已完成和不重要的收到后面。

- 全中文界面，日期格式 **DD/MM/YYYY**，时区 **Australia/Sydney**
- 电脑宽屏优先，手机上可以查看和快速记录
- 数据存 **Supabase 云端**（登录后电脑、手机同步）；没配置 Supabase 时以「本地模式」运行，数据只存在当前浏览器里
- 随时导出 Excel / JSON 备份

---

## 〇、最省事：已经托管在 claude.ai 上（不用 Supabase / Vercel）

网站已经发布成你 claude.ai 账号下的一个私有页面：https://claude.ai/artifact/PPkEdbfQ6zHHeaveFHhtwx

- **登录**：用你的 claude.ai 账号，不用另外注册。电脑浏览器、手机浏览器或 Claude App 里登录同一个账号就能打开。
- **数据**：存在这个页面自带的云端数据库里（最多 25,000 条记录，够用很多年），电脑和手机看到的是同一份。
- **谁能看到**：只有你。以后想和同事一起用，在页面的「分享」菜单里把同事设为「编辑者」即可；只给「查看」权限的人看不到任何数据。
- **和自建网站的区别**：导出 Excel / JSON 会先弹一个确认框；进度报告不能直接打印，改为「下载报告」，用浏览器打开后再打印或存 PDF。
- **更新**：改完代码后运行 `npm run build:artifact`，把生成的 `dist-artifact/student-tracker.html` 重新发布到同一个链接（让 Claude 发布即可），数据不会丢。

下面第一到第三步是另一种方式：自己用 Supabase + Vercel 部署。两种方式的数据可以通过「设置 / 导出」里的 JSON 备份互相搬。

## 一、先在本地试一试（5 分钟）

需要先装 [Node.js](https://nodejs.org/)（20 或以上）。

```bash
npm install
npm run dev
```

浏览器打开终端里显示的地址（一般是 http://localhost:5173），点「加载示例数据」就能看到效果，或者直接「导入 Excel」。

> 本地模式下数据只保存在这个浏览器里。正式使用请按下面的步骤配置 Supabase。

## 二、配置 Supabase（云端存储 + 登录）

1. 到 [supabase.com](https://supabase.com) 注册，新建一个项目（Region 选 Sydney 最快）。
2. 左侧 **SQL Editor** → New query → 把 [`supabase/schema.sql`](supabase/schema.sql) 整段粘贴进去 → **Run**。
   （可以重复运行，不会删数据。以后版本升级如果改了表结构，再运行一次即可。）
3. 左侧 **Project Settings → API**，复制 **Project URL** 和 **anon public key**。
4. 在项目根目录新建 `.env.local` 文件（参考 `.env.example`）：

   ```
   VITE_SUPABASE_URL=https://你的项目.supabase.co
   VITE_SUPABASE_ANON_KEY=你的anon key
   ```

5. 重新运行 `npm run dev`，会出现登录页。点「第一次用？注册」用自己的邮箱注册，去邮箱点确认链接后登录。
6. **建议**：注册好自己的账号后，到 Supabase **Authentication → Sign In / Providers → Email**，关掉 **Allow new users to sign up**，这样别人就不能注册了。
   （即使有人注册了，数据库的行级安全规则也保证每个账号只能看到自己的数据。）
7. **Authentication → URL Configuration** 里把 **Site URL** 改成你部署后的网址（见下一步），邮件里的确认/登录链接才会跳回正确的地址。

> 如果之前在本地模式里已经录了数据：先在「设置 / 导出」里导出 JSON 备份，登录云端后再「从 JSON 备份恢复」。

## 三、部署上线（免费）

推荐 [Vercel](https://vercel.com)：

1. 用 GitHub 账号登录 Vercel → **Add New → Project** → 选这个仓库。
2. Framework 选 **Vite**（会自动识别），Build Command `npm run build`，Output Directory `dist`。
3. **Environment Variables** 里加上 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`。
4. Deploy。完成后把网址填到 Supabase 的 Site URL（上面第 7 步）。

网站是纯静态页面（用 `#/` 路由），Netlify、Cloudflare Pages 等也可以，设置同上。手机上用浏览器打开网址，「添加到主屏幕」就像 App 一样用。

## 四、导入现有 Excel

左侧「导入 Excel」→ 选择文件（.xlsx；旧的 .xls 请先在 Excel 里另存为 .xlsx）。先预览，确认后才真正导入。

识别的列：学生姓名、负责手机、状态、业务分类、客户背景/备注、完整详情/历史进度、最新更新日、天数、任务优先级。

| 处理 | 规则 |
| --- | --- |
| 姓名 | 去掉括号里的状态词（完成 / 更新过 / 已更新 / 不用管了）；其他括号内容（如「年底毕业」「郭晨npy」「tingting手机」）移到背景备注 |
| 负责人 | `team2` → `team 2`；空的 → 未分配 |
| 历史进度 | 按日期拆成一条条时间线，识别 DD/MM/YYYY 和 DD/MM/YY；没写日期的片段标成「日期不明」 |
| 状态 | 直接用「状态」列；名字带「完成」但状态写「进行中」的列入冲突清单 |
| 优先级 | 「高」保留为高，其余算普通 |
| 最新更新日 | 不用 Excel 那一列，按导入后时间线最新的日期自动算 |
| 同名学生 | 系统里已有同名学生的，默认不导入（防止重复导入） |

导入后会生成 **导入确认清单**（左侧菜单），可以分几天慢慢处理：

- a) 备注里提到日期或期限的句子（如「10.30号补成绩单」「学签2月左右到期」「11.12号Orientation」）→ 一键设为待办或关键日期
- b) 提到 offer 的学生（如「UQ con offer」「Monash offer已下」）→ 一键补申请学校和 offer DDL
- c) 日期不明的记录 → 补日期
- d) 状态有冲突的学生 → 确认状态

申请学校表和签证进度第一版不自动解析，在学生详情里手动补。

## 五、每天怎么用

1. 打开网站默认进 **首页「今天要做什么」**：今天已跟进 X / Y 个学生、连续记录天数、Offer DDL 倒计时、到期待办、跟进到期、休眠结束、未来 60 天关键日期。
2. 点 **「开始今日巡检」**，系统把今天要处理的学生一张一张推给你（跟进到期、待办到期、offer DDL 14 天内、休眠结束、球在学生超过 7 天）：
   写一句进展回车保存 / 按 **C** 已检查没变化 / 📣 已提醒学生 / ⏰ 推迟 / **→** 下一个。处理完一个学生，它的跟进周期就从今天重新算。
3. 随时按 **N**（或右下角 ➕）快速记录：输入一两个字选学生 → 写一句话 → 回车。日期自动记，可以顺手设提醒、改状态。

### 键盘快捷键

| 键 | 作用 |
| --- | --- |
| `N` | 快速记录 |
| `/` | 搜索（学生列表页里聚焦列表搜索框） |
| `Enter` | 保存当前记录（`Shift+Enter` 换行；中文输入法选字时不会误保存） |
| `Esc` | 关闭弹窗或面板 |
| `→` / `←` | 巡检：下一个 / 上一个 |
| `C` | 巡检：已检查，没变化 |

## 六、提醒规则

| 内容 | 什么时候提醒 |
| --- | --- |
| Offer 接受截止日（DDL） | 提前 14 / 7 / 3 / 1 天各提醒一次（点「已提醒学生」后这一轮消掉），当天和过期标红；过期了还没接受会问「已接受 / 放弃 / 已延期」 |
| DDL 待确认 | 每 3 天提醒补上 |
| 押金/学费付款截止、补材料截止 | 提前 7 / 2 天 |
| 签证到期 | 提前 60 / 30 / 7 天 |
| 开学、Orientation 等关键日期 | 提前 7 天 |
| 跟进周期到期 | 学生出现在首页和巡检里（下次跟进 = 最后处理日期 + 跟进周期，可手动改） |
| 休眠结束 | 自动回到首页，显示当初的休眠原因 |
| 球在学生超过 7 天没有新记录 | 提醒去催 |

offer 状态改成「已接受」或「放弃」后，这条 offer 的 DDL 提醒自动停止。改申请状态、勾签证步骤时，系统会按阶段建议跟进周期（点「应用」才会改）。

## 七、数据说明

- **时间线只能追加不能删除**；可以编辑，但会显示「已编辑」并保留原文。「录入时间」自动记录、不能改；「发生日期」默认今天，可以改（用来补记前几天的事）。
- 状态变化、递交、offer、CoE、签证获批、付款自动算里程碑；手写备注可以手动标星。
- 「已检查，没变化」只刷新最后检查日期，不算「最后更新」；在时间线里显示成很淡的一行灰字，里程碑视图里不显示。
- 已预留「负责人」（学生）和「记录人」（每条时间线）字段，以后可以扩展成团队一起用。
- 备份：「设置 / 导出」里可以导出 Excel（每类数据一个工作表）和 JSON（完整备份，可以再导入恢复）。

## 八、开发

```bash
npm run dev        # 开发服务器
npm test           # 单元测试（日期、导入解析、提醒规则、业务操作）
npm run typecheck  # 类型检查
npm run build      # 打包到 dist/（自己部署用）
npm run build:artifact  # 打包成一个文件 dist-artifact/student-tracker.html（托管到 claude.ai 用）
node scripts/make-sample-xlsx.mjs   # 重新生成测试用的假 Excel
```

技术栈：Vite + React + TypeScript + Tailwind CSS + Zustand；Supabase（Postgres + Auth + 行级安全）。

```
src/
  lib/          类型、日期工具（悉尼时区）、常量、提醒引擎、搜索、导出
  importer/     Excel 导入：历史进度按日期拆分、日期/offer 提及识别、字段清理
  data/         数据层：store（乐观更新 + 写入队列）、业务操作、本地 / Supabase / claude.ai 三种存储、示例数据
  components/   界面组件：外壳、学生详情各模块、快速记录、通用 UI
  pages/        页面：首页、巡检、学生列表、详情、所有动态、未来几个月、导入、确认清单、设置、报告、登录
supabase/schema.sql   数据库结构和安全规则
tests/                单元测试
```
